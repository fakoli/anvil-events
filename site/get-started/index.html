Get started

Go from an empty directory to a durable local event journal, then exercise the isolated development fleet.

Local first

Start without a broker. This proves the event envelope, SQLite transaction, idempotency behavior, and inspection tools before network or host policy enters the picture.

Requirements: Python 3.11 or newer. The package has no runtime dependencies.
1

Install the exact release wheel.

$ python -m pip install https://github.com/fakoli/anvil-events/releases/download/v0.2.2/anvil_events-0.2.2-py3-none-any.whl

The v0.2.2 wheel SHA-256 is 23aac737604ce97a033e57c5adbf07c9fd0fe4bb8826706bb145a1b0cbca1cf3. The release is hosted on GitHub; there is currently no PyPI distribution.

2

Confirm the CLI.

$ anvil-events --help

Create a store

Global options come before the subcommand. Use a project-local root for this walkthrough so cleanup is obvious.

$ anvil-events --root ./demo-events init
backend: sqlite
database: .../demo-events/events.db

SQLite runs in WAL mode. The database owns event identity, pending and archived producer state, subscriber journal state, PubAck evidence, cursors, operation intent, reconciliation attempts, and retention metadata.

Record a desired event

record reads exactly one JSON object from standard input. It validates and accepts the event locally; it never waits for broker I/O.

PowerShell

$payload = @'
{"resource":"routing/clients","generation":1,"revision":"rev-1","content_sha256":"781a9e745454e30551907d683c956be69055528219e5f567a1ba1afe245e2c17","adapter":"router_config","artifact":"routing/clients","targets":["node-b"]}
'@
$payload | anvil-events --root ./demo-events record state.desired `
  --node node-a --producer node-a:router --operation-key demo-routing-1

Bash / zsh

$ printf '%s\n' '{"resource":"routing/clients","generation":1,"revision":"rev-1","content_sha256":"781a9e745454e30551907d683c956be69055528219e5f567a1ba1afe245e2c17","adapter":"router_config","artifact":"routing/clients","targets":["node-b"]}' \
  | anvil-events --root ./demo-events record state.desired \
      --node node-a --producer node-a:router --operation-key demo-routing-1

The response contains accepted, already_recorded, and the producer-scoped event_id. Run the exact command again: the same idempotency key and intent return the same event with already_recorded: true. Reuse that key for different intent and the transaction fails.

Inspect the journal

$ anvil-events --root ./demo-events status --json
{"archived":0,"backend":"sqlite","cursors":0,"database":".../demo-events/events.db","degraded":true,"facts":0,"journaled":0,"pending":1,"quarantined":0,"schema_version":1,"unresolved_operations":0}

$ anvil-events --root ./demo-events replay --lines 20
2026-… node-a:router:000001 state.desired corr=None

pending: 1 is expected: no broker has acknowledged the locally accepted event. degraded: true makes that unfinished delivery visible rather than silently discarding it.

Check dependency integrity

$ anvil-events verify ./demo-events
dependency graph: OK (1 events)

This check covers only explicit causes and producer-order DAG integrity. It does not claim database causal-consistency conformance.

Run the isolated development fleet

The checked-in Compose stack builds the exact package, creates and verifies the non-expiring ANVIL_EVENTS stream, starts a synthetic node reconciler, and exposes loopback health. Its broker port is not published to the host.

$ docker compose -f deploy/compose.yml up -d --build
$ docker compose -f deploy/compose.yml ps
$ curl http://127.0.0.1:9877/ready

Record the same sample desired event inside the events container, as shown in the repository README. The synthetic routing/clients adapter resolves the checked-in rev-1 artifact, applies it under the mounted volume, verifies the exact bytes, and records an outcome.

Development only. This Compose network is intentionally unauthenticated and must not be exposed to a LAN or private overlay network.

Configure a fleet node

Do this only after the local and Compose paths make sense. Start from deploy/fleet-node.example.toml and keep the real manifest outside the public product repository.

1. Establish broker identity

Fleet mode requires a verified tls:// endpoint plus authentication. The supplied NATS template demonstrates mTLS identity mapping, node-prefixed publish ACLs, and the consumer API, delivery, inbox, and ACK permissions required by one durable node.

2. Bind authority precisely

Set the node and outcome producer, exact allowed producers, artifact source, adapter destination, and authority_producers for every auto-applied resource. A producer allowlist alone never grants apply authority.

3. Pass credentials by reference

The service environment contains certificate paths and any token value. TOML may name the relevant environment variable but never stores the value.

4. Start one portable runtime

$ anvil-events --root /var/lib/anvil/events serve \
  --url tls://broker.example.invalid:4222 \
  --stream ANVIL_EVENTS \
  --subject 'anvil.events.v2.>' \
  --durable node-b-events \
  --config /etc/anvil-events/node.toml

Use the launchd, systemd, or container wrapper that fits the host. They all execute this same runtime and use a host-durable SQLite root.

Operate safely

GET /liveLocal SQLite is readable and runtime workers are alive.
GET /readyLiveness plus durable subscriber connectivity and no active pending-delivery error.
GET /A bounded JSON snapshot including pending work, unresolved operations, broker connection, reconciliation enablement, and last errors.

Readiness is not application acceptance. A real rollout still needs the desired revision, exact observed destination, correlated outcome, client reload/health evidence, broker-loss catch-up, and a tested rollback.

Before enabling a service

  • Install an exact reviewed wheel and verify its digest.
  • Initialize the store as the service user.
  • Validate the private manifest without changing an active destination.
  • Create or exactly verify the stream with a separate administrative principal.
  • Prove pending status while the broker is offline, then reconnect and catch up.
  • Preview every adapter and retain a rollback copy.
  • Stage one non-authoritative canary before the rest of the fleet.
