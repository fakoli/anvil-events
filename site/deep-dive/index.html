Deep dive

The guarantees are narrow on purpose—and explicit about where they stop.

Event identity

A v2 envelope is canonical JSON with an exact field set. Its identity is producer-scoped: event_id = producer + zero-padded producer_seq. The subject is derived from the envelope node and kind. The producer’s first token must equal the node.

{
  "version": 2,
  "event_id": "node-a:router:000123",
  "producer": "node-a:router",
  "producer_seq": 123,
  "node": "node-a",
  "kind": "state.desired",
  "subject": "anvil.events.v2.node-a.state.desired",
  "payload": {
    "resource": "routing/clients",
    "generation": 42,
    "revision": "immutable-revision",
    "content_sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "adapter": "router_config",
    "artifact": "routing/clients"
  },
  "causes": []
}

The complete envelope also includes RFC 3339 observed_at and emitted_at, a nullable correlation_id, and the exact v2 schema URI. A duplicate identity is accepted only when its canonical envelope is byte-for-byte equivalent. Any conflicting identity aborts the transaction.

Local acceptance transaction

OperationLedger.record binds the operation ID, idempotency key, producer, kind, correlation, intent, next producer sequence, canonical event, and pending state in one immediate SQLite transaction. This is the strongest “exactly one” boundary in the system: one local canonical event per idempotency key and intent.

Ordering without a global clock

Wall-clock timestamps describe observations; they do not decide correctness. The implementation uses two explicit orders:

producer_seqMonotonic identity and program order for events emitted by one producer.
generationMonotonic desired-state order for one logical resource authority.

Nodes may see unrelated resources in different orders. That does not prevent convergence. For one node and resource, the reconcile state records the generation owner. Lower generations are superseded; the same generation may not change revision, digest, adapter, or artifact.

No fleet-global sequence. Adding consensus or a universal sequencer would solve a problem this system does not have and would not make external side effects exactly once.

Delivery semantics

1Publish

Send canonical event with message ID.

2PubAck

Configured stream proves broker storage.

3Durable pull

Node receives or redelivers.

4Journal

Append locally before processing.

5Apply

Run one bounded adapter attempt.

6Verify

Classify and record outcome.

7ACK

Acknowledge durable processing.

What is guaranteed

  • Local event acceptance is durable and idempotent.
  • A pending publish completes only after exact-stream PubAck evidence.
  • Broker and subscriber delivery are at least once.
  • The local journal stores one canonical row per event identity.
  • Subscriber ACK follows durable local processing.

What is not guaranteed

  • No globally exactly-once external side effect.
  • No total order across independent producers or resources.
  • No fixed delivery latency during faults.
  • No automatic replay of an unclassifiable apply.
  • No application acceptance inferred from daemon readiness.

Why PubAck is narrow

A positive PubAck proves that the configured JetStream stored a publish at a broker sequence. It does not prove a node consumed the event, an adapter applied it, an application reloaded, or the fleet converged. Those facts require later journal, reconcile, observed-state, and outcome evidence.

The durable attempt starts as PREPARED. Preview is stored before policy is evaluated. A denied exact binding becomes AWAITING_APPROVAL and the broker delivery remains unacknowledged. Before calling the external adapter, the engine writes a separate applying marker while holding the cross-process resource lock.

After apply:

  • A successful verify records the resource generation and APPLIED.
  • A false or failing verification attempts rollback and records FAILED.
  • An apply exception records INDETERMINATE, because the external side effect may have occurred before the error became visible.
  • A previously applied event is re-verified on startup. Detected drift reopens the same attempt and reapplies the exact artifact.

Duplicate delivery is not duplicate apply

Redelivery of the same event reuses its deterministic reconcile operation. A distinct but equivalent desired event gets its own correlated outcome, while the already-owned generation is re-verified rather than blindly applied again.

Failure recovery

Broker unavailableLocal record succeeds; pending delivery remains visible; the delivery pump reconnects and publishes later.
Publisher disconnects after sendThe event remains eligible. JetStream message-ID deduplication and idempotent PubAck recording handle retry without changing event identity.
Node offlineThe durable stream retains history. On return, the node resumes from its durable consumer and evaluates the latest resource generations.
Invalid broker messageThe subscriber drops it without journaling or reconciling. Subject/body mismatch is invalid even when the envelope itself parses.
Invalid local pending rowRepair quarantines it, removes its pending role, marks a linked operation indeterminate, and writes a local degradation audit.
Crash during applyStartup finds the durable applying marker and classifies the attempt indeterminate. No automatic second apply occurs.
Observed drift after restartStartup resolves the exact desired artifact, verifies local state, and reopens/reconciles the existing applied generation when needed.

Security model

Transport cannot silently downgrade

Development plaintext is limited to literal loopback or a separately allowlisted single-label container host. Fleet mode requires a verified TLS endpoint plus username/password or mTLS. Standard INFO-then-TLS and explicit TLS-first are distinct, tested handshakes.

Authentication is not authorization

A node certificate or broker user establishes a principal. Broker ACLs restrict the subject prefix. Envelope validation binds the producer to its node. The node manifest separately decides whether that producer may automatically apply one resource through one adapter.

Events are capability-free

Payload validation rejects credential-shaped keys and URLs. Resource, revision, adapter, and artifact names are bounded portable identifiers. Adapters obtain destinations and executable structure only from local configuration.

Artifact bytes are part of intent

A resolver must return the requested immutable revision. The engine verifies its canonical SHA-256 before preview or apply. HTTP resolution is authenticated, HTTPS-only in fleet mode, rejects redirects, and pins local file access through opened parent directories.

Twelve executable invariants

These are implementation properties with hermetic regressions and separate external gates where a broker, TLS policy, or real application is involved.

Immutable event identity

One event ID and producer sequence identify one canonical envelope; conflict aborts.

Atomic local acceptance

Idempotency, intent, producer sequence, operation, and pending event commit together.

PubAck gates completion

Only valid evidence from the configured stream can archive known pending work and advance its cursor.

Poison data is visible

Corrupt pending state is quarantined and audited; invalid broker input never enters the journal.

Generation cannot equivocate

One node/resource generation has one desired owner; lower or conflicting generations cannot apply.

Events carry no authority

Local manifests own paths, origins, credentials, commands, validation, and exact policy bindings.

Apply is classified

A resource lock serializes the attempt; verification gates applied state; ambiguous external effects remain indeterminate.

ACK follows processing

Storage or processor failure remains unacknowledged; awaiting approval can be redelivered after policy changes.

No transport downgrade

Fleet endpoints require verified TLS and authentication; subject integrity is checked end to end.

Migration is non-destructive

Strict locked snapshots import transactionally; malformed or changing legacy sources roll back and remain intact.

Dependency claims are narrow

verify checks only explicit-cause and producer-order graph integrity.

Recovery history persists

The default stream does not expire desired history before a tested snapshot/compaction path exists.

Research-to-design map

The papers shaped the questions and boundaries. They are not cited as proofs that this implementation inherits their guarantees.

LogPlayer

Contributes the separation of safety, recovery, target state, and liveness. anvil-events uses JetStream recovery and durable generation state; it does not reproduce LogPlayer’s indexed-WAL algorithm or claim globally exactly-once apply.

Delivery, consistency, determinism

Motivates stating delivery, consistency, deterministic replay decisions, and external nondeterminism as separate axes rather than compressing them into “exactly once.”

Checking causal consistency

Motivates precise history models and bad-pattern checks. The product keeps only a dependency-DAG checker; it lacks the read/write object semantics required for causal-consistency conformance.

Lamport’s Arrow of Time

Supports the design instinct to avoid treating physical timestamps as universal order. It is context, not a correctness proof; the implementation’s scoped sequence and generation rules stand on their own tests.
